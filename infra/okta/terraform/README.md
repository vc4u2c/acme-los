# Okta Terraform Notes

This folder is the Terraform-shaped version of the Okta admin setup.

It is **not** the main recommended path today.

## Why It Exists

We want a future-friendly promotion path for Okta config that can eventually move cleanly through environments.

Terraform is still the cleanest target shape for that.

## Why It Is Not The Default Today

In this repo's current Okta dev org, the provider write path has not been reliable enough to treat Terraform as the main bootstrap tool.

What that means in practice:

- `terraform plan` has been useful
- `terraform apply` has not been reliable enough on the clean service-app OAuth path
- the working dev bootstrap path today is `npm run okta:bootstrap -- <env>`

So Terraform here is best understood as:

- a secondary path
- a future promotion shape
- a place to keep Terraform-oriented config honest

## Current Inputs

Terraform consumes:

- `infra/okta/environments/*.json`
- `infra/okta/brand/acme-los.json`
- `tmp/okta/<env>.terraform.auto.tfvars.json`

The tfvars file is generated by:

```powershell
npm run okta:render -- dev
```

## Current Auth Modes

The wrapper supports two admin auth modes:

- `OKTA_API_TOKEN`
- `OKTA_TERRAFORM_CLIENT_ID` plus a private key

Today, if you are trying to get work done locally, prefer the bootstrap script instead of Terraform.

## When To Use This

Use Terraform here only if you are:

- testing whether the provider write path has improved
- experimenting with a future CI/CD promotion path
- intentionally working on the Terraform layer itself

Do **not** treat it as the default day-to-day setup path.

## Commands

Initialize:

```powershell
npm run okta:terraform -- dev init
```

Preview:

```powershell
npm run okta:terraform -- dev plan
```

Apply:

```powershell
npm run okta:terraform -- dev apply -- -auto-approve
```

## Practical Recommendation

For this repo today:

- use `okta:render` to generate local config
- use `okta:bootstrap` to actually set up the dev org
- treat Terraform as secondary until the provider path is reliable enough
